# 192.168.0.158 → Proxmox node: migration checklist

Goal: retire Ubuntu on `.158` (worker-01) and reinstall it as a Proxmox node in
`prx-cluster-01`, without losing data or breaking the LAN. Work top to bottom —
**don't start the install (step 5) until every box above it is ticked.**

Inventory taken 2026-10-06 (see [192.168.0.158.md](192.168.0.158.md) for the
stack details). Commands that need `sudo` on `.158` require its password; there is
no passwordless sudo there.

## 0. Prerequisites (hardware & network)

- [ ] **Wired Ethernet.** `.158` is currently on a USB Wi-Fi adapter (`wlxd03745645b11`); the onboard Intel NIC `enp0s31f6` is unplugged. Proxmox VM bridges (`vmbr0`) can't run over Wi-Fi and corosync over Wi-Fi is unreliable — run a cable to `enp0s31f6` before installing.
- [ ] **Static IP.** The current `.158` lease belongs to the Wi-Fi adapter's MAC. Pick the Proxmox IP (keep `192.168.0.158`, set statically in the installer) and make sure the router won't hand it out via DHCP.
- [ ] **BIOS:** "Intel Virtualization Technology" and "VT for Direct I/O" enabled (both currently active), UEFI boot.
- [ ] Proxmox VE 9.x USB stick ready (same version as the other nodes: `pveversion` on `.2`).

## 1. Back up everything (nothing is deleted yet)

Backup target needs ≥ 220 GB free (external USB disk, or the laptop) — the Immich library has **no second copy today**.

- [ ] **Immich library** — `rsync -aH --info=progress2 ubuntu@192.168.0.158:/mnt/longhorn/immich-library/ <backup>/immich-library/`
- [ ] **Immich database** — `sudo docker exec immich_postgres pg_dumpall -U postgres | gzip > immich-db-$(date +%F).sql.gz`, plus `/home/ubuntu/immich-app/.env` and `docker-compose.yml`
- [ ] **pihole** — Settings → Teleporter → Export (blocklists, local DNS records, DHCP reservations if any)
- [ ] **LocalStack secrets** — list them (`aws --endpoint-url=http://192.168.0.158:4566 secretsmanager list-secrets`) and copy each into Vault: `vault kv put secret/<name> ...`
- [ ] **Old Vault** — anything not already in `tf-vault-01`? Copy it over, then `vault operator raft snapshot save old-vault.snap` (address `https://127.0.0.1:8200` on `.158`, old root token)
- [ ] **Monitoring** — `sudo tar czf monitoring.tgz -C /data monitoring` (`prometheus.yml`, rules, `loki.yml`, `grafana/grafana.db`); commit the configs to `external-services/monitoring/` for the new monitoring role
- [ ] **uptime-kuma** — Settings → Backup → Export, or `tar czf uptime-kuma.tgz ~/uptime-kuma`
- [ ] **n8n** — `sudo docker exec n8n n8n export:workflow --all --output=/home/node/workflows.json` and `export:credentials --all`; copy both out (credentials export is encrypted with the instance key — save `N8N_ENCRYPTION_KEY` too)
- [ ] **OpenVPN** — `sudo tar czf openvpn.tgz /etc/openvpn` (CA, server keys, client configs), only if keeping the VPN
- [ ] **Bots & projects** — `tar czf home-projects.tgz ~/infra-briefs-bot ~/sre-telegram-bot ~/jordan-leadgen ~/flughafendb` (include any `.env`/tokens); `crontab -l > crontab.txt`
- [ ] **ollama** — `ollama list` → note model names (re-pull later, not worth backing up)
- [ ] *(optional rollback)* image the Ubuntu SSD from a live USB: `dd if=/dev/sda bs=4M status=progress | gzip > <backup>/158-ubuntu-sda.img.gz`
- [ ] Spot-check: open a few restored photos, `zcat immich-db*.sql.gz | head`, Teleporter file imports in a test pihole

## 2. Move services off `.158`

For each: bring up the new home, verify, then stop the old one on `.158`.

- [ ] **pihole** — new home up with the Teleporter backup imported; `dig @<new-ip> google.com` works
- [ ] **Immich** — decide: run it on the new Proxmox node with the existing HDD passed to the VM (step 6), or restore elsewhere now. Until then it stays where it is
- [ ] **Secrets** — every LocalStack/old-Vault secret is in `tf-vault-01`; `cloudflare-token-sync-cronjob` reads from Vault (or is replaced)
- [ ] **Monitoring** — new Prometheus/Grafana running and scraping; dashboards restored or rebuilt
- [ ] **uptime-kuma, n8n** — restored on their new homes
- [ ] **Bots** — infra-briefs-bot and sre-telegram-bot running as K8s CronJob/Deployment (secrets from Vault); verify one scheduled run
- [ ] **OpenVPN** — replaced by Teleport, or moved; update client profiles if the endpoint changes

## 3. Repoint everything that still uses `.158`

- [ ] **Router DHCP DNS** — change DNS #1 from `192.168.0.158` to the new pihole (or the router) and renew leases; `nmcli dev show | grep DNS` on a client confirms
- [ ] **Router port-forward** UDP 1194 → `.158` (OpenVPN): remove or repoint
- [ ] `terraform/k8s-addons/teleport.tf` — `immich` and `localstack` apps point at `http://192.168.0.158:…`: update or remove, `terraform apply`
- [ ] `cert-manager/cloudflare-token-sync-cronjob.yaml` — still reads LocalStack at `192.168.0.158:4566`
- [ ] Old (Ansible) cluster's `teleport-kube-agent` (`teleport/values.yaml`) — `teleport.homebytes.space` now resolves to the **new** cluster's CA; re-join it with a new token or confirm it's retired
- [ ] `RBAC/prometheus-external.yaml` — RBAC for the external Prometheus on `.158` (the new cluster's equivalent lives in `terraform/k8s-addons/monitoring.tf`)
- [ ] `terraform/terraform.tfvars` — drop `VAULT_ROOT_TOKEN`/`VAULT_KEY_*` (old Vault); delete `terraform/vault-cluster.json`
- [ ] `ansible/external-hosts.ini`, `ansible/README.md`, root `README.md`, `homelab-diagram.drawio` — remove `.158`
- [ ] `grep -rn 192.168.0.158 .` in the repo returns only historical docs

## 4. Final check before wiping

- [ ] Leave `.158` running for a day with its services stopped (`sudo docker compose down` in each stack; `sudo systemctl disable --now teleport vault openvpn-server@server ollama sre-bot-listener`; `crontab -r` after saving it) — anything that breaks still depended on it
- [ ] Backups from step 1 exist off-box and were spot-checked
- [ ] Nothing in step 3 is unticked

## 5. Install Proxmox

- [ ] Boot the installer; **target disk = the Kingston SSD `sda` (223.6 GB) only.** Do not select the WD HDD (`sdb`, holds the Immich library) — the installer only erases the disk you choose
- [ ] Management interface: `enp0s31f6` (wired), static `192.168.0.158/24`, gateway `192.168.0.1`, hostname e.g. `pve-03`
- [ ] After first boot: `apt update && apt full-upgrade`, same repos as the other nodes, `pveversion` matches

## 6. Join the cluster and make it Terraform-ready

- [ ] `pvecm add 192.168.0.2` on the new node (it must have no VMs yet); `pvecm status` shows 4 nodes, quorate
- [ ] Quorum: 4 votes tolerates only 1 failure, same as 3 — consider a QDevice (e.g. a Pi) for a 5th vote
- [ ] `terraform@pve`'s ACL at `/` already covers the new node — nothing to add; `snippets` is already enabled on the cluster-wide `local` storage
- [ ] Build its templates (Packer images / cloud-init template) and add `node_name = "pve-03"` VMs in `terraform/main.tf`
- [ ] **Immich disk:** mount the HDD on the node (`/dev/disk/by-id/ata-WDC_WD5000AZLX-*`) and either pass it whole to the Immich VM (`qm set <vmid> -scsi1 /dev/disk/by-id/...`) or add it as Proxmox directory storage
- [ ] Optional GPU: see the GPU passthrough notes (IOMMU groups, vfio-pci, `hostpci` + PCI hardware mapping in Terraform)
- [ ] Update [192.168.0.158.md](192.168.0.158.md) / root README to describe `.158` as Proxmox node `pve-03`
