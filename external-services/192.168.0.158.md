# 192.168.0.158 (worker-01)

Standalone Ubuntu host running Docker Compose stacks directly on the
machine. It is **not** part of the Kubernetes cluster managed by
[ansible/hosts.ini](../ansible/hosts.ini) (masters `.157`, workers `.155`,
`.156`, `.159` — `.158` is absent). The host does have leftover
`kubeadm.sh` / `kube-flannel.yml` / `admin.conf` files under
`/home/ubuntu`, apparently from an earlier, abandoned attempt to make it
a cluster node — treat those as historical, not active.

SSH: `ssh ubuntu@192.168.0.158` (the `ubuntu` user is in the `docker`
group; there is no passwordless `sudo`).

## Docker Compose stacks

### pihole — `/home/ubuntu/pihole/docker-compose.yaml`
Repo copy: [pihole/docker-compose.yaml](pihole/docker-compose.yaml)

| Service | Image | Ports | Purpose |
|---|---|---|---|
| `pihole` | `pihole/pihole:latest` | `53/tcp+udp` (DNS), `80/tcp` (web UI) | Network-wide DNS + ad blocking |
| `pihole-exporter` | `ekofr/pihole-exporter:latest` | `9617` | Prometheus metrics for pihole, scraped by the monitoring stack below |
| `netalertx` | `ghcr.io/netalertx/netalertx:latest` | `20211` (UI), `network_mode: host` | Network device/presence scanner; pulls pihole data via `PIHOLE_URL` |

- **Stray file**: `docker-compose.notworking.yml` in the same directory is an
  abandoned earlier revision (no exporter/netalertx, different upstream DNS,
  port 443 uncommented). Nothing references it — candidate for deletion.
- **Secret hygiene**: `FTLCONF_webserver_api_password` and `PIHOLE_TOKEN` are
  set to smart-quoted `‘pinhole’` (curly quotes, not straight `'`) — this is
  very likely not the literal value Pi-hole/netalertx receive, and either way
  it's a weak, plaintext, non-rotatable secret sitting in a compose file.
  Good first candidate to move into the LocalStack secrets manager stack
  below.

### monitoring — `/data/monitoring/docker-compose.yml`
Repo copy: [monitoring/docker-compose.yml](monitoring/docker-compose.yml)

| Service | Image | Ports | Purpose |
|---|---|---|---|
| `prometheus` | `prom/prometheus:v2.51.2` | `9090` | Metrics store/scraper; also mounts `k8s-ca.crt` / `k8s-token` to scrape the k8s cluster remotely |
| `sloth` | `ghcr.io/slok/sloth:latest` | — (runs once, exits) | Generates `ase-market-slo-rules.yaml` for Prometheus from `ase-market-slo.yaml` |
| `loki` | `grafana/loki:3.0.0` | `3100` | Log aggregation |
| `grafana` | `grafana/grafana:10.4.2` | `3000` | Dashboards, exposed at `grafana.teleport.homebytes.space` via the Teleport app |

- **Stray file**: `docker-compose.yml.bak` (older revision, missing the SLO
  rules mount and Teleport domain config) — a manual pre-edit backup that was
  never cleaned up, exactly the kind of drift this doc is meant to stop.
  It's `root`-owned with no passwordless `sudo` on this host, so it wasn't
  deleted automatically; run `sudo rm /data/monitoring/docker-compose.yml.bak`
  to finish the cleanup. (The matching stray copy at
  `/home/ubuntu/monitoring-docker-compose.yaml` and
  `pihole/docker-compose.notworking.yml` have already been removed.)
- **Secret hygiene**: `GF_SECURITY_ADMIN_PASSWORD=change-me` — the literal
  placeholder value, on a Grafana instance reachable externally via Teleport.
  Second candidate for the secrets manager.
