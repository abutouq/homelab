# 192.168.0.158 (worker-01)

Standalone Ubuntu host, **not** part of the Kubernetes cluster managed by
[ansible/hosts.ini](../ansible/hosts.ini) (masters `.157`, workers `.155`,
`.156`, `.159` — `.158` is absent). It has leftover `kubeadm.sh` /
`kube-flannel.yml` / `admin.conf` files under `/home/ubuntu`, apparently
from an earlier, abandoned attempt to make it a cluster node — treat
those as historical, not active.

It runs two Docker Compose stacks (pihole, monitoring) *and* it is the
self-hosted **Teleport control plane** for the whole homelab — see
[Teleport](#teleport-self-hosted-control-plane) below. That makes this
host more critical than "a couple of side services": if it's down,
`teleport.homebytes.space` is unreachable and so is everything proxied
through it (Grafana, pihole admin, the k8s cluster's Teleport app/kube
access, `ase-market`'s Teleport entry).

SSH: `ssh ubuntu@192.168.0.158`. The `ubuntu` user is in `sudo` (password
required, not passwordless) but **not** in `docker` — so `docker`/`docker
compose` commands need `sudo`, and there's no way to run them
non-interactively over SSH without the password.

## Docker Compose stacks

### pihole — `/home/ubuntu/pihole/docker-compose.yaml`
Repo copy: [pihole/docker-compose.yaml](pihole/docker-compose.yaml)

| Service | Image | Ports | Purpose |
|---|---|---|---|
| `pihole` | `pihole/pihole:latest` | `53/tcp+udp` (DNS), `80/tcp` (web UI) | Network-wide DNS + ad blocking |
| `pihole-exporter` | `ekofr/pihole-exporter:latest` | `9617` | Prometheus metrics for pihole, scraped by the monitoring stack below |
| `netalertx` | `ghcr.io/netalertx/netalertx:latest` | `20211` (UI), `network_mode: host` | Network device/presence scanner; pulls pihole data via `PIHOLE_URL` |

- **Stray file**: `docker-compose.notworking.yml` in the same directory is an
  abandoned earlier revision (no exporter/netalertx, different upstream DNS,
  port 443 uncommented). Nothing references it — candidate for deletion.
- **Secret hygiene**: `FTLCONF_webserver_api_password` and `PIHOLE_TOKEN` are
  set to smart-quoted `‘pinhole’` (curly quotes, not straight `'`) — this is
  very likely not the literal value Pi-hole/netalertx receive, and either way
  it's a weak, plaintext, non-rotatable secret sitting in a compose file.
  Good first candidate to move into the LocalStack secrets manager stack
  below.

## Teleport (self-hosted control plane)

Config: `/etc/teleport.yaml` (root-owned, `0600` — not directly readable by
`ubuntu`; get it via `sudo cat` on the box). Repo copy of the parts that
matter for app routing: [teleport/teleport.yaml](teleport/teleport.yaml).
This is **not** just an agent — it's the actual Teleport cluster:

| Service role | Listen | Purpose |
|---|---|---|
| `auth_service` | `3025` | Cluster auth/CA — everything else (incl. the in-cluster `teleport-kube-agent`, see [../teleport/values.yaml](../teleport/values.yaml)) trusts this |
| `proxy_service` | `443` (`teleport.homebytes.space`) | TLS termination (cert/key under `/home/ubuntu/teleport-tls/`) + reverse proxy for SSH, app, and k8s traffic |
| `ssh_service` | `3022` (default) | Lets this host itself be reached via `tsh ssh` instead of raw SSH |
| `app_service` | via proxy | Reverse-proxies registered web apps (below) |

### Planned: add `localstack`

Once the LocalStack stack is deployed (see below), add this to
`app_service.apps` in `/etc/teleport.yaml` and `sudo systemctl restart
teleport`:

```yaml
  - name: localstack
    uri: http://localhost:4566/
    public_addr: ""
    insecure_skip_verify: false
    use_any_proxy_public_addr: false
```

This can't be applied by SSHing in as `ubuntu` — the file is root-owned
and there's no passwordless `sudo` on this host, so it has to be applied
by whoever has the `sudo` password.

## Planned: LocalStack Secrets Manager

Scaffold: [localstack/docker-compose.yml](localstack/docker-compose.yml) — its
own stack and network on port `4566`, meant to be deployed to
`/home/ubuntu/localstack` so it doesn't collide with the two stacks above.
Not yet deployed. Once it's up, migrate the two flagged secrets
(pihole API password/token, Grafana admin password) out of the compose
files and into it.

**Image pin**: the compose file pins `localstack/localstack:3.0`, not
`:latest` — confirmed newer releases (2026.6.2) refuse to start at all
without a paid `LOCALSTACK_AUTH_TOKEN`, even for community-tier services
like Secrets Manager. `3.0` boots with no token required.

**Cluster-side sync**: the `ase-market-helm` namespace's `ase-market-helm-ase-credentials`
Secret can be kept in sync with a `secretsmanager` entry here via a small
CronJob (image: [`../secrets-sync`](../secrets-sync), source of the
`aabutouq/secrets-sync` image) rather than a full External Secrets Operator
install — see `secretsSync` in [`../helm/ase-market/values.yaml`](../helm/ase-market/values.yaml)
(disabled by default until this host's LocalStack is actually deployed and
seeded). Note it only polls on a schedule and writes a plain Secret — pods
read Secret-sourced env vars once at container start, so a rotated value
still needs those pods restarted to take effect.
